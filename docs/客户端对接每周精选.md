# 客户端对接：模型点赞与每周精选

> 适用端：微信小程序（BlockLab）
> 文档版本：2026-11-18，对应后端 test 分支 commit `6793105`

## 1. 概述

本功能提供两个客户端能力：

1. **模型点赞**：登录用户对积木模型点赞/取消点赞（切换式），模型列表与详情会返回点赞数和当前用户是否已点赞。
2. **每周精选**：获取当前周的管理员精选模型（一周一个），管理员可手动设置或按点赞榜单自动产生。

## 2. 基础约定

- **Base URL**：
  - 测试环境：`https://api.ai-youtoo.cn/blocklab-test`
  - 生产环境：`https://api.ai-youtoo.cn/blocklab`
- **请求格式**：`Content-Type: application/json`
- **统一响应结构**：

```json
{
  "success": true,
  "message": "...",
  "data": { }
}
```

- **鉴权方式**：请求头携带登录接口返回的 token

```
Authorization: Bearer <token>
```

- **登录**：`POST /api/auth/login`，body 为 `{ "code": "<wx.login 的 code>" }`，响应 `data.token` 即后续鉴权凭证。**点赞必须登录**；精选查询登录与否均可（登录后行为一致，当前版本精选响应与登录态无强关联）。

## 3. 接口详情

### 3.1 获取当前周精选模型

- **接口**：`GET /api/models/featured`
- **鉴权**：可选（不强制）
- **说明**：返回当前周（本周一 00:00 为起点）的精选模型；管理员每次读取时会实时重算当前周记录。一周内精选模型可能因管理员切换模式而变化，客户端每次展示时实时拉取即可。

**成功响应**（有精选时）：

```json
{
  "success": true,
  "message": "Featured model fetched successfully",
  "data": {
    "id": 9,
    "name": "荷兰风车",
    "partCount": 9,
    "thumbnailUrl": "https://.../thumbnail.png",
    "manualUrl": "https://.../windwill.pdf",
    "ioFileUrl": "https://.../windmill.io",
    "model3dUrl": "https://.../windmill2.glb",
    "createdAt": "2026-10-13T11:37:52.175Z",
    "modelTypeId": 4,
    "modelTypeName": "示例分类",
    "source": "manual",
    "weekStart": "2026-11-16T00:00:00.000Z"
  }
}
```

**无精选时**：`success` 仍为 `true`，`data` 为 `null`。

**字段说明**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | number | 模型 ID |
| `name` | string | 模型名称 |
| `partCount` | number | 零件数 |
| `thumbnailUrl` | string \| null | 缩略图 |
| `manualUrl` | string \| null | 说明书 PDF |
| `ioFileUrl` | string \| null | .io 源文件 |
| `model3dUrl` | string \| null | 3D 模型文件（glb） |
| `createdAt` | string | 模型创建时间（ISO 8601） |
| `modelTypeId` / `modelTypeName` | number / string \| null | 分类 |
| `source` | string | 精选来源：`manual` 手动 / `weekly_likes` 按周点赞 / `total_likes` 按总点赞 |
| `weekStart` | string | 本周起始时间（ISO 8601） |

> 注意：精选响应中**不含** `likeCount` 等点赞字段。如需展示精选模型的点赞数，请用其 `id` 调 3.3 的详情接口。

### 3.2 点赞 / 取消点赞（切换式）

- **接口**：`POST /api/models/{id}/like`
- **鉴权**：**必须登录**（未登录返回 401）
- **说明**：切换式——已点赞则取消，未点赞则点赞，无需客户端区分调用两个接口。

**成功响应**：

```json
{
  "success": true,
  "message": "Liked",
  "data": {
    "liked": true,
    "likeCount": 1
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `liked` | boolean | 本次操作后的状态：`true` 已点赞，`false` 已取消 |
| `likeCount` | number | 操作后该模型的最新总点赞数（可直接用于 UI 刷新） |

**错误码**：

| HTTP | error | 场景 |
|---|---|---|
| 400 | `INVALID_MODEL_ID` | id 非正整数 |
| 401 | — | 未登录或 token 失效 |
| 404 | `MODEL_NOT_FOUND` | 模型不存在/已删除 |

### 3.3 模型列表 / 详情中的点赞字段

模型列表（`GET /api/models`）和模型详情（`GET /api/models/{id}`）均为**可选鉴权**：

- 带登录 token 调用时，`liked` 反映当前用户是否已点赞；
- 未登录调用时，`liked` 恒为 `false`。

列表每一项和详情 `data` 中均包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| `likeCount` | number | 总点赞数 |
| `weeklyLikeCount` | number | 滚动近 7 天点赞数 |
| `liked` | boolean | 当前用户是否已点赞 |

## 4. 对接建议

### 4.1 点赞按钮（乐观更新示例）

```js
async function toggleLike(model, token) {
  // 乐观更新：先改 UI，失败再回滚
  const oldLiked = model.liked;
  model.liked = !oldLiked;
  model.likeCount += oldLiked ? -1 : 1;
  try {
    const res = await wx.request({
      url: `${BASE}/api/models/${model.id}/like`,
      method: 'POST',
      header: { 'Authorization': `Bearer ${token}` }
    });
    // 用服务端返回值校准
    model.liked = res.data.data.liked;
    model.likeCount = res.data.data.likeCount;
  } catch (e) {
    model.liked = oldLiked;
    model.likeCount += oldLiked ? 1 : -1;
    wx.showToast({ title: '操作失败', icon: 'none' });
  }
}
```

### 4.2 每周精选展示

```js
async function loadFeatured() {
  const res = await wx.request({ url: `${BASE}/api/models/featured`, method: 'GET' });
  if (res.data.success && res.data.data) {
    // res.data.data.weekStart 可用于判断"新一期"（本地缓存对比，弹新精选提示）
    renderFeatured(res.data.data);
  } else {
    // 本周暂无精选，隐藏入口或展示占位
  }
}
```

### 4.3 注意事项

1. **精选可能为空**：管理员未设置且自动榜单为空时 `data` 为 `null`，客户端需处理空态。
2. **精选一周一条但内容可变**：`weekStart` 同一条记录在一周内可能被管理员重算覆盖，不要把精选内容做长期缓存；如做「新一期提醒」，用 `weekStart` 变化判断而不是 `id`。
3. **精选指向的模型可能被删除**：此时接口同样返回 `data: null`，客户端按无精选处理即可。
4. **点赞前检查登录态**：401 时引导用户先登录，不要静默重试。
5. **切换式语义**：同一个接口重复调用即切换状态，按钮的最终状态以响应 `data.liked` 为准。
